# SCULP OS 3.0 Phase 2.5：Gmail 智能邮件整合日志

日期：2026-11-12（多伦多）。基于 Phase 1 开发候选；状态为开发/测试候选，**真实 Gmail 未授权、生产未发布**。

## 审计结论

正式工作区、客户/订单 RPC、私有通讯记录、现有 reminders、AI 服务及角色验证继续复用。仓库和当前执行环境未发现 Google OAuth Client 配置，也没有既有邮件组件/表；没有读取任何 Google 邮箱、OAuth 明文或邮件正文。只读生产元数据表明 Phase 1 新接口仍需单独部署，因此不将“Phase 1 开发确认”写成“生产已上线”。

## 已完成候选代码

| 模块 | 实现 |
| --- | --- |
| 授权与连接 | 只读 Gmail OAuth、离线授权、S256 PKCE、一次性 hashed state、发起用户活跃业务角色复查、固定回调与返回地址、预期工作室邮箱检查 |
| 凭据 | 独立 AES-GCM key 加密 access/refresh token 和 verifier；只在私有服务端处理；浏览器不读 token；日志仅安全错误码 |
| 同步 | 按业务邮箱或明确业务标签分批导入；history 游标、分页续跑、20 封上限、去重、租约、失效游标回扫、限流/网络错误重试、手动同步和历史导入 |
| 客户 | worker 按非测试询盘邮箱规范化精确匹配/创建客户，不按姓名合并；客户邮件入口可维护联系邮箱，重复地址要求人工核对；打开客户后可触发一次授权范围同步 |
| 订单 | 邮件根据明确且唯一的订单编号候选关联；多订单不强行归属；人工关联/解除保留 tombstone，避免下次同步重新加回 |
| 邮件 UI | Communications 邮件中心；客户和订单区域；标题搜索、待回复/未关联筛选、时间、方向、附件名称、正文纯文本、Gmail 原件入口；长邮件截断提示 |
| AI | 显式 opt-in；现有服务端配置生成分级字段/摘要与英文回复草稿；worker 可另启用每轮最多一条摘要；不写确认订单字段，没有 Gmail 发送权限或发送接口 |
| 跟进 | 内部 reminders 复用，默认新邮件/2 小时/48 小时/5 天规则可配置；已发送必须有 SENT 与工作室发件地址证据；人工暂停/拒绝/确认与相应停止规则；无新增设备推送 |
| 安全 | 私有表 RLS、撤销浏览器全表权限、业务角色 RPC、只读 Gmail HTTP 路径、纯文本显示、AI 无工具执行、断开使租约失效并清理本地正文/摘要/草稿 |

## 尚未完成的外部验收

Google Cloud Project/Gmail API/Consent Screen/Web Client、正确工作室邮箱、服务端 secret、安全 key、回调登记、真实 OAuth、真实往返邮件、真实模型质量、真实账户/设备与生产发布均未完成。本地/CI 模拟通过不能替代它们。

## 明确限制

1. UI 列表最新 50 封以内，历史通过标题/客户/订单筛选和 Gmail 原件查看；没有完整 Gmail 分页搜索产品。
2. 日期/标题推测不会自动关联订单；同一 thread 的新消息也不会仅凭旧邮件关联盲目归入同一服务。
3. 邮件跟进状态独立，AI 不直接把 CRM 标为 Lost/Confirmed，也不修改订单或付款；由人核对后走原流程。
4. 内部提醒保存在任务系统；不是新增手机推送。首次历史导入不批量生成过期历史提醒。
5. 草稿可编辑、内部保存、复制并打开 Gmail，不创建 Gmail 草稿，不发送、不删除 Gmail 原邮件。多人并发草稿编辑还需真实验收。
6. 无关邮件只做必要消息头匹配，不保存正文或传入 AI；业务地址本身也需由工作室审核适用范围。
7. 本候选未安装 cron；调度部署脚本与真实授权后验收见设置指南。
