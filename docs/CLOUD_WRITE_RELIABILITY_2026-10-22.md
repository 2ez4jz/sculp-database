# 云端业务写入可靠性修复

日期：2026-10-22（America/Toronto）。范围：正式工作区的异常处理，不改变业务流程、页面结构、正常录入/核对/确认步骤，也不修改 GitHub Actions。

## 已实现

- 合同/收退款收到服务器成功确认后，即使详情重新读取失败，也保持已保存状态，阻止同一表单再次创建付款或合同操作。
- 订单、合同、询盘及新订单录入统一区分数据库明确拒绝、版本/权限变化和结果不明的网络故障。结果不明时保留原始请求编号及完整请求；不根据错误文案中的“客户”“日期”等词猜测事务已回滚。
- 合同和询盘遇到版本冲突时释放等待状态，冻结旧表单并提示重新查询，避免无限重试过期版本。权限拒绝同样要求重新验证后读取。
- 询盘正在保存或结果不明时，刷新、切换筛选及新增入口不会销毁原表单和重试编号。并发查询的旧结果不会覆盖正在保存的列表；过期合同查找结果不会改变已确认/正在提交的表单。
- 正式工作区汇总订单编辑、收款、询盘和录入的未确认写入状态；主动退出登录前提示处理同一笔请求；刷新/关闭页面触发浏览器原生离开提醒，销毁工作区时移除监听。
- 修复两处既有测试日期假设：取消测试使用实际多伦多日期及月份；签约日期断言由数据库按多伦多日期格式化，避免主机时区影响。

## 发布及边界

本轮是开发分支修复，是否部署以合并和 Pages 结果为准。不修改生产数据库、Edge Functions、模型、权限结构、业务状态流或外部通知。

重试编号仍保存在当前页面内存，浏览器提醒并不保证用户强制关闭后恢复。未将客户原文、收款凭据或令牌新增写入 localStorage。断电、系统终止或其他标签强制登出后仍需登录查询正式记录，不能声称已完成跨会话恢复。真实同事、实体手机麦克风与持续多日使用仍需人工验收。本轮未部署 V3 任务迁移、未新增自动提醒和记忆模块。
