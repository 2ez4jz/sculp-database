# SCULP OS 3.1：客户档案与跟进任务

日期：2026-11-16（多伦多）。状态：前端、数据库和聊天版本说明已上线；JZ 已确认当前版本验收完成。

验收补记：JZ 于本轮 V3.2 开发前明确表示“目前版本已验收”。V3.1 因此作为已验收基线；以下原报告中的待验收事项保留发布时语境，不再表示 V3.1 尚未获用户验收。后续客户编辑、负责人改派与历史导入已在 [V3.2](V3.2_RELEASE.md) 单独发布并等待该版验收。

## 用户可见变化

- CRM 新增客户档案：来源、联系方式、城市、语言、婚礼日期、内部备注，历史及未来订单分页查看，并可打开原订单或创建关联任务。
- 客户目录支持姓名、邮箱和电话查询，不按同名自动合并客户。
- 日程与任务新增分页及状态筛选；可以完成人工跟进任务、取消、改期和重新打开。
- 修改需明确确认；服务器检查版本冲突，重复请求保留同一编号；保存回执丢失时冻结表单并提供原请求重试。
- 任务截止日期按多伦多日期处理；原工作台、订单、询盘及手机固定导航继续复用。

## 数据与权限

复用 `reminders`、`clients` 和 `client_private`，不使用历史未部署的 `crm_tasks`。本次独立迁移新增提醒版本字段、递增触发器、私有请求回执及受限 RPC，不导入业务或测试记录。客户详情和任务操作仅开放给当前活跃 owner/operations；公开包装函数为 SECURITY INVOKER，私有函数再次验证身份，私有回执表开启 RLS 并撤销浏览器权限。

聊天只更新功能说明，没有新增任务写入或 Gmail 工具。发布聊天说明时须以生产 Edge 源码为基线，不能用仓库较旧的 handler 覆盖线上长期记忆能力。Gmail 后续配置暂停；本次没有邮箱授权、同步或调度变更。

## 验证与部署

本地新增交互与数据测试覆盖：人工确认、完成/取消/改期/重新打开、同请求重放、跨账户重放拒绝、版本冲突、权限隔离、已删除客户及订单排除、分页、HTML 转义、过期读取保护和多伦多夏令时边界。真实 PostgreSQL 并发检查与完整浏览器回归已通过。

部署前只读取生产结构、约束和聚合指纹；不公开客户或账户详情。发布顺序为本条增量数据库迁移、通过检查的前端、按现网基线合并的聊天说明，最后核对线上资源及受限 RPC。不得根据提交或 CI 推断部署成功。

## 回退与验收边界

前端可恢复至本轮发布前版本；保留任务版本及请求审计，避免丢弃已发生的新修改。若关闭新版写入，撤销新增任务写 RPC 即可，不删除客户/订单或用旧备份覆盖业务。完整客户编辑、负责人改派、重复任务、独立周/月日程和日报周报留待后续；真实账号跨设备与实体手机仍需实际验收。
