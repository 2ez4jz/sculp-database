# SCULP OS 3.0 Gmail：数据与权限

新增候选迁移 `20261112192341_gmail_communication.sql`。没有应用生产，不重建或删除原表。

| 私有实体 | 用途 |
| --- | --- |
| `gmail_accounts` | 账户状态、AES-GCM 密文、游标、续跑状态、租约、规则、AI opt-in；V1 单活跃邮箱，email 唯一，可调整索引支持多邮箱 |
| `gmail_oauth_states` | 哈希 state、加密 PKCE verifier、发起用户、10 分钟时效；使用后删除 |
| `gmail_messages` | account + Gmail ID 唯一；thread ID、纯文本、方向、时间、附件名称；不下载附件 |
| `gmail_client_links` | 一封邮件可关联多个业务客户；只按明确地址自动匹配，人工可另确认 |
| `gmail_order_links` | 人工关联/解除和明确订单编号关联；解除保留 tombstone，不被下次同步重新加回 |
| `gmail_sync_jobs` | 状态、数量和安全错误码，不保存正文/token |
| `gmail_ai_results` | 分级信息/摘要与回复草稿；不会更新订单字段 |
| `gmail_client_states` | 人工确认的邮件跟进状态，不能冒充 CRM 自动成交/流失状态 |
| `gmail_followups` | 邮件 + 规则唯一，关联既有 reminders 内部任务，避免定时重复创建 |

Thread ID 以消息字段及索引表达，当前不建立空的线程表。既有 `clients/client_private/bookings/website_enquiries/reminders/audit_events` 继续复用。

全部新表在 `sculpy_private`、开启 RLS，撤销 PUBLIC/anon/authenticated 表权限。service-only 编排函数只向 `service_role` 开放；普通管理员不能读取密文凭据。业务浏览器通过 `sculpy_gmail_read` 和明确确认的 `sculpy_gmail_action` 访问，无全表直接授权。两个 public 包装函数为 SECURITY INVOKER；私有实现使用固定空 search_path、完全限定对象和 active owner/operations 检查。作者姓名或前端 persona 不是授权来源。

Worker 单账户租约，每批最多 20 封；保存与 cursor checkpoint 都核对租约，断开清除租约。失败保留旧游标、任务记录安全错误码，等待重试。并发 worker 不能同时持有同一账户租约。历史搜索先捕获 historyId，完成全部地址查询及分页后再从该基准增量读取，避免首次导入期间漏新邮件；history 404 转回业务范围完整扫描。客户范围变化会触发补查，而非跳过旧邮件。

非测试询盘地址由 worker 在连接后按规范化精确邮箱匹配/创建 CRM 客户，带事务锁和审计。不在官网请求内同步调用 Google，因此 Google 故障不阻止询盘入库。未接通 Gmail 前，不触发这条客户补录路径。多条同地址询盘复用客户，已有多个同地址客户不自动合并。

正文只保存纯文本/HTML 转文本并转义显示，不运行邮件脚本、图片追踪或下载附件。极长邮件有截断和原邮件入口。客户/订单删除不会调用 Gmail 删除接口，所有 Gmail API 业务请求为 GET。

AI 需账户 opt-in，用户可手动生成，后台摘要需另外启用 `GMAIL_AUTOMATIC_AI`；每轮最多一条。拒绝读取已断开的邮件，断开期间已发出的模型请求无法追回，但返回结果不能入库。草稿编辑没有完整多人乐观版本冲突 UI，正式多人使用前应验收。

回滚：停用 scheduler，断开连接，恢复旧前端；保留表/关联/审计，不 DROP 业务数据。必要时 revoke 新 public/private 写 RPC 执行权。加密 key 和 Vault 备份及恢复需在部署环境演练，不能仅凭虚构恢复测试当作生产可恢复。
