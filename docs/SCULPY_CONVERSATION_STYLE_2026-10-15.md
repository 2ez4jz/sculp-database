# SCULPY 自然交流、直白表达与适量引导

日期：2026-10-15（多伦多）。仅 SCULPY / SCULP Studio；不迁移到 MEMORA 或共享产品默认设置。

## 改动

- 从固定经营助手改为可聊天、解释、写作、创意与共同思考的AI伙伴；只有问题需要业务事实时才查订单。欢迎页提供“看看最近的情况、找点灵感、随便聊聊”。
- 用普通人能听懂的话，少用获客、核对口径等顾问术语；表达直接、有代入感，多用“你先看这几单”“这件事值得盯住”。有依据的机会可以明确鼓劲，鼓励要接具体依据与动作，不用未经验证的赚钱保证。
- 专属语气放在独立的 `supabase/functions/sculpy-chat/studio-tone.js`；MEMORA未修改。
- 经营回答默认解释数字意义、可能原因和一个具体下一步；明确要求只要数字／一句话时缩短。闲聊和概念解释不强拉回经营，也不习惯性每轮追问。
- 发现旧展示层把大部分解释与排行表折叠，只展示首段、通用金额与限制。现在核心解释、列表和相关排行表直接显示；完整原文仍可展开，不改写存储的原回答。
- 一段经营分析最多提供两个可点问题，继续追问后不再反复推荐，用户明确要求问题建议时可再次提供。仅点击才请求模型；不会自动提问。输入框已有草稿时保留草稿。
- 修复概念解释中明确标为“比如”的数字例子误触无来源业务金额保护、导致SDK意外回退的问题。仅概念问题的示例获得例外，实际业务查询和未标明的金额仍需工具依据。
- 大白话也保留财务准确性：客单价是平均成交价，不等于实际收款；收款也不等于利润。

## 验证

- 本地完整154项：153通过、0失败、1项外部PostgreSQL条件跳过。
- 桌面与390px手机检查：核心解释和排行表无需展开即可见；推荐问题最多两个；点击带上原对话；草稿不丢；不重复推荐；不额外自动请求；没有横向溢出。
- GitHub完整浏览器／数据库／备份恢复检查通过：[38786129150](https://github.com/2ez4jz/sculp-database/actions/runs/38786129150)。
- v33中间测试发现概念示例触发回退，已修复。v34六类真实请求全部HTTP 200、无意外回退：闲聊、概念解释、欢迎语创意、改写成大白话、业务排行、明确一句话。普通对话未调用业务报表；业务数字调用了报表。
- 所有线上测试只使用临时编造的内联订单和新写的测试问题，没有读取或发送本地客户目录与保存的私人聊天。
- v35追加两项真实请求全部HTTP 200、无意外回退：客单价与收款的区别；可比套餐下的经营机会及先做什么。回答能直接指出值得盯住的订单，并把机会落在具体动作上。
- 最终源码检查通过：[38786627662](https://github.com/2ez4jz/sculp-database/actions/runs/38786627662)，包括完整浏览器、数据库和备份恢复验证。SCULPY Edge Function v35 已启用。
