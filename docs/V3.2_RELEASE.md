# SCULP OS 3.2 客户维护与历史导入

日期：2026-11-16（多伦多）。状态：前端、数据库和聊天版本说明已验证部署；本版用户验收待完成。V3.1 已由 JZ 确认验收完成，是本轮基线。

## 更新范围

- 客户档案内编辑姓名、称呼、联系方式、来源、城市、语言、婚礼日期、标签与备注；先核对差异和可能重复的客户，再人工确认保存。并发修改及联系方式单独变化都会使旧预览失效；保存回执不明可重试原请求。
- 新建任务可选择已有活跃 owner/operations 负责人；现有任务可改派，记录前后负责人并保留版本冲突保护。我的/团队范围与原有状态筛选组合使用，不新增员工 CRM 权限或外部通知。
- 客户和订单 UTF-8 CSV 模板、字段映射、原文件行号和逐行字段预览。文件最多 2 MiB/2000 条，每次人工确认最多 100 条；可排除错误行、核对已有客户后重新预览。先导入客户，再关联订单。
- 重试、重复文件、批内相同内容与外部来源编号分别核对；来源编号对应不同内容时要求人工处理。批次以事务保存，不留下半批数据；结果可打开实际记录。

## 数据口径与边界

只使用现有 clients、client_private、reminders、bookings，新增私有命令/导入回执表和受限接口。公开包装为 SECURITY INVOKER，私有业务接口复查有效业务角色；私有回执开启 RLS 且不开放浏览器直接读取。

订单服务需匹配已有服务代码。完整日期与具体开始时间是保存前置条件；缺失时间的行阻止保存，不使用默认时间。当地时间使用 America/Toronto，夏令时不存在时段拒绝保存，重复时段需明确偏移。未知价格保留 null，预算不作为成交价；币种和状态必须明确。现有匹配订单保留原资料与编号，新增订单使用现有编号分配器；不创建收付款/退款/结算流水，也不补造签约日期。

Gmail、社媒、独立周/月日程、日报周报和财务扩展不在本轮。没有新增模型调用或聊天写入工具。现网聊天后端须以实际源码为基线合并功能说明，保留长期记忆与既有工具。
