# V2.3 错误与修复记录

- 旧订单编辑会重写/清空签约时间：签约、改价、取消改用专用受控命令；旧入口不能覆盖签约历史。日期编辑追加状态/档期快照。
- 原收款的 refunded 状态无法表达退款发生月份：保留原收款，使用同一 payments 表追加有日期、关联原收款的退款。旧版 gross RPC 排除退款方向，避免退款被当作新到账。
- 同一合同多条询盘重复归属金额：保留所有关联，按 originating_enquiry_id 只归一次合同金额。
- 网站表只在正式库存在：补入兼容基线；生产仅部署 V2.3 依赖，没有顺带启用其他任务功能。
- 第一次隔离测试发现测试 profile 参数同时推断 text/enum：显式转换测试参数，实际生产 schema 不受影响。
- 浏览器 SDK 模拟对象缺少链式 in/limit：修复测试边界，使其与真实客户端 builder 一致。修复账号登录、订单录入及 V2.3 测试中的模拟接口；没有放松实际断言。
- 大批迁移出现 Invalid or expired requestState：先核实没有执行，再按 SQL 语句边界分段应用；一次同秒迁移版本冲突完整回滚，确认函数不存在后重试，最终部署均有历史记录。
- 测试探针清理的原始写接口也返回 requestState 错误：采用保留原始记录、明确过滤内部验收签名的只读业务视图和 SQL 口径。正常询盘数、无效询盘数、成交率和所有渠道指标均不包含这条内部探针，保留技术可追溯记录。没有清除或改写真实客户资料。
- Git HTTPS 推送无法读取凭证：核实既有公开仓库和当前连接的 admin/push 权限后，通过已连接 GitHub 写入相同 tree SHA；提交仅含源代码及虚构测试，正式备份未加入仓库。

- 最后检查发现当天手动询盘补录会因操作时刻晚于签约而被误拒绝：仅有日期的 firstContact 按本地日零点解析；保留既有精确时间，新增同日先签后补录的数据库断言。
