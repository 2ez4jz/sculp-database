# SCULPY V2.2 工作日志

日期：2026-10-14（Toronto；UTC记录可能为10月15日）。基线 Git：6a784c1；基线 Edge：sculpy-chat v21。

## 审查事实与开放问题

已核实：默认聊天是 Responses API + gpt-6-luna/low，所有回答强制JSON；Agents SDK 0.20.0 / gpt-4.1-mini 仅用于显式开启的全局Demo经营分析，历史被拼成一个文本；三份专业Skill Markdown没有被运行时加载；Supabase保存最近100轮并发版本检查，模型读取最近12轮；没有审批式长期政策记忆。真实账号已有服务端Auth、角色与RLS保护，保留。

推断：固定格式和大量无关指令可能影响自然交流，但没有单变量实验不能把质量变化全归因于某一项。更高模型与推理配置也不能保证像ChatGPT，需实际样本评价。

开放问题：完整真实账户浏览器验收、真实隔夜长期记忆（本轮是模拟隔日与重新检索）、实际录音噪声/口音。测试不把Demo身份切换当正式授权证明。

## 已做修改

- 精简核心提示词，保留权限、事实、未知数据、人工确认边界；三个现有专业Skill按问题与上一轮意图选择，运行时内容与源文件一致性测试。
- 普通回答不再强制JSON；明确记录/变更保留结构化卡片契约。没有写入工具，金额/时间变更仍只存待审核建议。
- Demo默认使用SDK的原生MemorySession，保持消息角色；由前端现有隔离历史恢复，未误称为永久Provider会话。只读报表和订单查询均有次数、超时、范围限制；每次请求用独立OpenAIProvider，避免共享Key全局状态。
- 候选模型为gpt-6-sol / medium；需以真实请求决定保留或回退。通过服务器环境变量可切换模型与推理，不接受客户端任意模型名。
- 正式账号继续使用已有JWT过滤、月报工具、会话并发检查；统一升级表达与推理配置，不将Demo工具搬入正式库。
- 长期经营记忆：管理员提出pending、确认active、纠错待审、确认时旧版superseded、撤销revoked；每次动作留审计，版本号防陈旧确认。员工/匿名不可读取。每轮使用调用者JWT检索最多20条有效记忆，不包含过期版本，也不复制客户订单数据。
- 管理员聊天偏好下加入经营记忆面板，支持读取/文本检索、提交、确认、更正、撤销；不自动提取讨论，不替用户批准政策。

## 回滚

Git以6a784c1为原始基线。前端可通过`?demo=1&agent=legacy#sculpy`选择原对话引擎（仍使用本次共享核心规则）；完整回滚应恢复基线Git对应前后端。设置SCULPY_AGENT_DEMO_ENABLED=false可停SDK，SCULPY_CHAT_MODEL=gpt-6-luna、SCULPY_REASONING_EFFORT=low可恢复原默认模型配置。将基线提交的sculpy-chat目录重新部署可恢复v21逻辑，需保留verify_jwt=false及函数内Auth验证。记忆表为新增结构；后端回滚后保留只读数据与审计，不删表或正式记录。禁止用`git reset --hard`直接覆盖他人的新提交。
